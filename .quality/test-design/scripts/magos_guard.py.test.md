## Test Strategy

All tests live under `tests/codex/guard/` and run with `pytest` in the lane worktree (runtime host cases stay in the
separate project test worktree described in `AGENTS.md`). Three levels:

1. **Pure unit tests** import `scripts/magos_guard.py` as a module: manifest parsing, normalisation, the glob-intersection
   dynamic programme (checked against a brute-force oracle that enumerates a universe of candidate paths), the decision
   table, message rendering in both languages, the command lexer and detector (including repository redirects and the
   missing-directory rule), the tamper filter, claim parsing and writing, version comparison.
2. **Real-Git integration tests** build throw-away repositories in `tmp_path` with real linked worktrees (committed-ahead
   branch, dirty worktree, untracked file, rename, delete, detached worktree with commits, merge or rebase in progress,
   locked and prunable worktree, remote-tracking branch ahead of the target, bare repository, case collision, unborn
   repository) and drive the CLI in process (`main(argv)`) and as a subprocess. Git runs with an isolated `HOME`,
   `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM`, and the isolated gitconfig sets `core.longpaths=true` so deep
   temporary paths work on Windows.
3. **Host-protocol and process tests** feed Claude, Codex and Hermes PreToolUse payloads (including PowerShell BOM and
   CRLF stdin, `Monitor` and shell MCP tools) to `hook`, run the embedded `HOOK_SH` through real Git (`arm`) and directly
   under Git's `sh`, run `run-guard.cmd` through cmd.exe and `sh`, and run two concurrent planners in separate processes.
   Redirect cases run at hook level from three session directories: a directory outside any repository, another clean
   repository, and another repository that holds a lane and a claim for the same name.

Interpreters: the suites pass on the minimum Python 3.9, on CPython 3.12 (`C:/Python312`) and on CPython 3.14 (the
`python3` the hooks run under). The lane gate runs the whole guard suite twice, once with `C:/Python312/python.exe` and
once with `python3` (3.14), because Windows path handling differs from Python 3.13 on and a run on one interpreter does
not prove the other; inside each run, TC-106 compares hook verdicts with the launcher's interpreter and TC-107 replays
the path-sensitive payloads under both `os.path.isabs` behaviours. Every test module starts with `from __future__ import annotations` so it imports on
3.9, and the stdlib-only check falls back to a fixed module list where `sys.stdlib_module_names` is missing. The CI
workflow `.github/workflows/test.yml` runs the guard suite, the contract unittest suite, both contract runners with
`--check` and the version agreement check on windows-latest and ubuntu-latest with Python 3.9, 3.12 and 3.14. Test
helpers start every subprocess with `stdin=DEVNULL` and without inherited console handles, so the suites run under
pytest's default capture on the pymanager 3.14 shim; tests of console-gated commands (`override`, `arm`, `disarm`,
`install`) patch `user_console`. Fixture repositories are created under a temporary directory. Windows-only cases (the
executable search order, cmd.exe) are skipped elsewhere; POSIX-only cases run on the ubuntu leg.

The frozen detector corpus (`tests/codex/guard/data/corpus.jsonl`, 1,155 labelled command strings) is replayed with
precision and recall floors; every residual miss and false positive is listed in `data/known_gaps.json`. The
echo-piped-into-sh detector cases and their expected names live in a data file under `tests/codex/guard/data/`, so no
shipped text line has that shape. Coverage is measured with coverage.py (line coverage) through the commands in
`.quality/qguard.json`, for `scripts/magos_guard.py` and for every tracked source of the project (`__init__.py`,
`scripts/sync_hosts.py`), each strictly above 90 percent; the two other files are exercised in process by
`test_project_sources.py` (`scripts/sync_hosts.py` has its own test design).

## Boundary & Failure Cases

- Empty manifest, 200 and 201 entries, 1024 and 1025 character entries, a manifest file outside and inside a worktree,
  UTF-8 with BOM, UTF-16 and ANSI encodings.
- Repositories with no commits, detached HEAD, bare repository, submodule, no merge base (unrelated history gives the
  warning UNRELATED_HISTORY and the branch is ignored), more than 120 unmerged local branches (UNKNOWN TOO_MANY_CLAIMANTS),
  more than 300 remote-tracking branches (warning REMOTE_TRUNCATED with the count), more than 5,000 paths in one claimant.
- Git failures: missing `git` or an exhausted budget (an error, never "not a repository"), a vanished working directory,
  non-zero exit with and without stderr, timeout, `WinError 1455` retried twice; each ends as UNKNOWN GIT_FAILED,
  GIT_MISSING or BUDGET_EXCEEDED and a denied `plan` or `check`; under `--json` the deny object is printed. Git 2.35 and
  older is reported by `doctor`.
- Locale and encoding: non-ASCII branch and path names with `core.quotepath` forced off, case-insensitive collisions,
  Unicode normalisation forms, trailing dots and spaces, Windows reserved names, Git Bash path spellings (`/c/Users/x`),
  POSIX-rooted spellings that map to no drive (`/does/not/exist`) on interpreters before and after Python 3.13.
- Repository redirects: a relative `--git-dir` before or after `git -C` (joined to the `-C` directory either way), an
  exported relative `GIT_DIR` followed by `cd` (joined to the new directory), a `GIT_DIR` that names a linked worktree's
  `.git` file or a bare repository directory, an empty `GIT_DIR=`, a redirect to a directory that is not a repository, a
  dynamic value, an `unset`, `export -n`, `env -u`, `Remove-Item Env:` or empty PowerShell assignment of `GIT_DIR`
  (ends the redirect), a removal spelling outside that list (the recorded redirect stays), a redirect from a session
  directory outside any repository; `GIT_COMMON_DIR` alone, beside `GIT_DIR`, beside `--git-dir` (which replaces
  `GIT_DIR` only), relative after `-C`, dynamic, missing and removed.
- Definite and possible changes: a `cd` that is the first command of a list, one after `&&` with and without a later
  `;` or `||`, one after `||`, inside each compound command and branch, in a function body and a PowerShell script
  block (defined, called), in a background list and in cmd (where `&` is sequential), behind a program wrapper and
  behind `command` / `builtin`, under `env -C` / `sudo -D` (static and dynamic), in substituted text before and after the
  creation, inside a quoted string; a `fi` inside `$( )` within an outer `if`; redirections after `cd`.
- Scopes: a `cd`, `pushd`, `Set-Location` or redirect change inside a group, inside the first, a middle or the last
  command of a pipeline, inside nested groups, through `eval`, `iex`, `source`, `.` and a PowerShell script; a
  creation inside the group or the evaluated text (judged in the changed state only); a child shell's change (never
  reaches the line); a plain `cd` after a group (one state again); a `)` that closes `$(` inside a group, a quoted `(`
  inside a group and a group inside `$( )` (one stack pairs the parentheses); exactly eight
  states (walked) and nine (denied).
- Missing directories: `cd` with no argument or a dynamic target (unknown repository), a chain of relative `cd` after a
  missing one, and the accepted over-denials `cd missing && git switch -c x` (Git would not run) and
  `mkdir sub && cd sub && git init && git switch -c x` inside a repository that has another lane.
- Tools: an MCP tool whose name contains a shell word without being one (`read_terminal`) is matched by the Claude matcher
  and returns `{}`; a hooked tool without a string command; a Codex argv list.
- Claim store: a claim of a newer format without a `branch` line (named by its file), a `v` that is not an integer
  (unreadable), a claim written with CRLF or a BOM by hand, a claim path that resolves outside `<store>/claims`.
- Install and doctor: version comparison as integer tuples (`1.0.10` is newer than `1.0.9`), a copy without
  GUARD_VERSION (compared by sha256 and treated as older), `install` run from the copy itself (copies nothing),
  a missing `guard/generated/` directory (refresh command printed for every host), a Hermes home from `HERMES_HOME`,
  `%LOCALAPPDATA%` and `~/.hermes`.
- Concurrency: a claim written while a reader lists, two lock holders, a claim file removed between the existence test
  and the read in the git layer (treated as absent, transient deny), two planners passing the early name check before
  either holds the lock.
- Hostile input: huge stdin, invalid UTF-8, JSON that is not an object, unknown tool names, nested wrappers deeper than 3,
  base64 that is not UTF-16LE, command lines built to trigger regex backtracking (linear time), pipe-to-shell inputs
  whose option values could be read as wrappers or assignments (one reading per word, linear time), a line whose walk
  exceeds the budget (here-documents nested in eight states: denied in about a second), a command longer than
  200,000 characters (not inspected, denied once lanes exist), planted `git.exe`, `py.cmd` and `py.bat` in the working
  directory, newlines in `--worktree` and `user.name`.
- Regression: a lane that merely checks out files without modifying them never claims them; a denial never creates a
  branch, directory or administrative directory; an override never survives a changed target sha; no hook denies a
  commit, merge, edit or read inside an existing lane; a claim in the session repository never allows a creation in
  another repository.
