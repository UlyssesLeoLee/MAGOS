# Technical Design: `scripts/magos_guard.py`

Source: `scripts/magos_guard.py`

Source-SHA256: `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`

## Responsibility

`magos_guard.py` is the lane guard of the MAGOS package. It is a single stdlib-only Python 3.9+ file that makes the
rule "a lane is a registered file manifest before it is a branch" enforceable instead of advisory.

The guard stops the lane that is being created, never a lane that already exists:

- A new branch or worktree must have a planned file manifest registered before the creating command runs.
- If any planned file overlaps a file that another branch, worktree or declared lane has changed, is changing or has
  declared, the creation is denied before it happens and every conflicting branch and worktree is named.
- Existing branches and worktrees are only read. No hook denies a write, commit or merge inside an existing lane.
- "Changed" is measured against the integration target. Every worktree contains every file; a lane claims a file only
  if it differs from the target in that file (committed, staged, unstaged, untracked or in progress) or declared it.

The file holds six cooperating parts.

1. **Manifest and overlap engine.** Entries are normalised (NFC, case-folded, separators unified, trailing dots and
   spaces stripped) and compared with an exact glob-intersection dynamic programme at character level and at path level.
   A `**` segment matches any number of directories; `*` and `?` never cross `/`; brackets are ordinary characters.
   Entry-versus-path and entry-versus-entry use the same function, so declared manifests of lanes that do not exist yet
   collide with each other.
2. **Evidence gatherer.** A Git runner (argv lists, scrubbed environment, `-z` machine formats, per-call timeout and a
   total deadline) enumerates claimants: every non-bare worktree, every local branch not merged into the target, every
   unmerged remote-tracking branch, and every open claim. Committed evidence is the three-dot diff against each merge
   base minus content the target already holds. Uncommitted evidence is `status --porcelain=v2 -z --untracked-files=all`
   (a rename claims both names). A merge, rebase, cherry-pick or revert in progress is a warning; `git am` or unreadable
   operation metadata is unknown.
3. **Claim store.** `<git-common-dir>/magos/claims/<branch>.claim` files, written under an OS file lock with a
   temporary file and `os.replace`, plus an append-only `audit.log`. The store is shared by all worktrees, is never part
   of a work tree and is not carried by fetch, push, clone, bundle or mirror.
4. **Command detector.** A lexer for bash, PowerShell and cmd that unwraps `bash -c`, `pwsh -Command`,
   `-EncodedCommand`, `cmd /c`, `env`, `sudo`, `xargs` and similar wrappers (depth 3), tracks `cd` and `git -C`, and
   recognises lane-creating git commands and harness tools. Dynamic words (`$x`, backticks, `%x%`) in a lane-creating
   position are treated as unparseable.
5. **Host hook entry.** `hook <claude|codex|hermes> pre-tool` reads one PreToolUse payload from stdin and prints either
   `{}` (allow) or one deny object that carries the full conflict message.
6. **Git layer.** A pure POSIX `sh` `reference-transaction` hook, embedded as a constant and written by `arm`. It needs
   no Python and vetoes the creation of any `refs/heads/*` name that has no claim, whatever tool ran Git.

## Dependencies

Upstream: Python 3.9+ standard library only (`argparse`, `hashlib`, `json`, `os`, `re`, `subprocess`, `threading`,
`unicodedata`, `msvcrt` or `fcntl`). Git 2.31+ (`status --porcelain=v2`, `worktree list --porcelain -z`,
`for-each-ref --merged`, `reference-transaction`). No network access, no `fetch`, no `push`.

Downstream callers:

- `hooks/hooks.json` (Claude Code plugin hook wiring) and `hooks/run-guard.cmd` (polyglot launcher) call
  `hook claude pre-tool`.
- The user-level Codex and Hermes hook entries generated by `install` call `hook codex|hermes pre-tool`.
- `references/lane-split.md` and `SKILL.md` tell agents to run `check`, `plan`, `list` and `release`.
- `/GitIntegrate`, `/GitRecon`, `/GitCleanup`, `/GitConverge` and `/GitSweep` read or release claims through `list` and
  `release` as `references/commands.md` describes; the read-only commands never write claims.
- The package keeps its skills-only manifests: `.claude-plugin/*`, `plugin.json`, `plugin.yaml`, `__init__.py` and
  `scripts/sync_hosts.py` are unchanged. `install` copies the guard to `~/.magos/guard/` for Codex and Hermes because
  `sync_hosts.py` copies only `SKILL.md`, `references/*.md` and the command adapters.

## Public Contract

Invocation: `py -3 -X utf8 -B scripts/magos_guard.py <command> [options]` (`python3` on POSIX). Global options anywhere:
`--repo DIR` (default cwd), `--lang zh|en` (default `zh`, environment `MAGOS_LANG`), `--json`. Input is read as bytes
(UTF-8, BOM tolerated); output is UTF-8.

Commands an agent may run: `check`, `plan`, `list`, `release`, `doctor`. Commands only the user runs: `override`, `arm`,
`disarm`, `install`.

- `check --branch B (--paths P... | --manifest FILE|-) [--target T]`: read-only verdict, no lock, writes nothing.
- `plan --branch B (--paths P... | --manifest FILE|-) [--worktree PATH] [--amend] [--target T]`: gathers evidence
  outside the lock, takes the lock, re-reads the claims, judges, writes `claims/B.claim` atomically and appends an audit
  line. Identical entries are a no-op (exit 0). Different entries need `--amend` (exit 14 otherwise); an amend is judged
  with the lane's own claim excluded, and a removal-only amend skips the overlap check. A branch that already exists with
  no open claim is refused (exit 15). On success it prints the creation command, for example
  `git worktree add <path> -b <B> <target>`.
- `list [--drift] [--json]`: each claim as `planned` (no branch), `active` (branch unmerged or checked out) or `idle`
  (merged, no worktree). `--drift` reports files in the lane's footprint matched by none of its entries; it never denies.
- `release --branch B [--reason R]`: deletes the claim and audits it. Refused with exit 16 while the lane is `active`.
- `override --fingerprint FP --reason R`: refuses (exit 17) unless stdin and stdout are a real console; the user retypes
  the fingerprint; writes a one-shot record valid for one hour that the next `plan` with the same denial fingerprint
  consumes.
- `hook <host> pre-tool`: the PreToolUse entry. Allow is `{}` with exit 0. Deny is exactly one ASCII-escaped JSON
  object on stdout, exit 0, nothing on stderr:
  `{"decision":"block","reason":MSG,"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":MSG}}`.
  A deny is never an exit code.
- `arm [--strict] [--lang L] [--dry-run]`: writes `<hooks dir>/reference-transaction` (a foreign hook is chained as
  `.magos-prev`), `<store>/ARMED`, `lang`, `guard` and, with `--strict`, `strict` plus an exemption file per existing
  branch; disables `maintenance.pack-refs` and `gc.packRefs` for the repository. Refuses (exit 3) when `core.hooksPath`
  is set, hook directories differ across worktrees, or `.magos-prev` already exists. Idempotent.
- `disarm [--dry-run]`: removes `ARMED` and `strict`, deletes the hook if it is MAGOS's and restores `.magos-prev`;
  keeps claims and audit.
- `install --host claude|codex|hermes [--dry-run] [--home DIR]`: copies `scripts/magos_guard.py` and
  `hooks/run-guard.cmd` to `<home or ~/.magos>/guard/{scripts,hooks}/` and writes the exact host snippet to
  `guard/generated/<host>.json|yaml`. It never edits `~/.claude/settings.json`, `~/.codex/hooks.json` or Hermes config.
- `doctor`: checks Python, Git, mode, hook uniformity, hook content, claim parsing and orphan claims; in an armed
  repository it proves the backstop by trying `git branch __magos_selftest`. Exit 1 on any problem.

Exit codes: 0 allow, registered or ok; 2 usage or not a repository; 3 arm refused; 10 CONFLICT, NO_MANIFEST,
UNPLANNABLE, UNPARSEABLE or PROTECTED; 11 UNKNOWN (also any engine exception or exhausted budget: plan and check fail
closed); 12 INVALID_MANIFEST; 13 LOCK_TIMEOUT (30 s); 14 LANE_EXISTS; 15 BRANCH_EXISTS; 16 BLOCKED (release);
17 CONSOLE_REQUIRED.

Claim file (LF, the git layer reads only line 1): `state=active`, `v=1`, `branch`, `worktree`, `target`, `base`,
`created`, `by`, `override`, then one `entry=<raw entry>` line per manifest entry. Store layout:
`<git-common-dir>/magos/{ARMED,strict,lang,guard,exempt/,claims/,override/,audit.log,lock}`.

Verdict (`--json`): `{decision, code, conflicts:[{key, branch, worktrees, planned, evidence:[{kind committed|uncommitted|declared,
files, matched, theirs}]}], unknowns, warnings, target:{name,sha,confidence}, fingerprint, overridden, message, exit_code}`.
The fingerprint is the first 12 hex digits of SHA-256 over the canonical denial (claimant keys, evidence kinds and files,
unknown codes, target sha); manifest entries are not part of it, so changing the repository voids an override.

Invariants:

1. Creation is denied before it happens; a denial leaves no branch, worktree directory or administrative directory.
2. Existing lanes are never stopped, modified, stashed, merged or moved; the guard only reads them.
3. Unknown is not safe: an ambiguous target, unrelated history, `git am`, unreadable operation metadata, more than 120
   unmerged claimants, a Git failure or an exhausted budget (18 s total, 30 s per Git call) deny creation in `plan`,
   `check` and in an armed repository; in auto mode the host hook allows an unanalysable branch-only creation.
4. Hard overlap is a direct path, directory prefix, glob, rename side, case or Unicode collision, or a declared manifest
   against a manifest. Warnings never deny: inferred target, remote freshness, operation in progress, repository not armed.
5. The only writes are claim and audit files (under the lock), override records, and the files `arm`, `disarm` and
   `install` print. `check`, `list` and `hook` never write.
6. Engagement: ARMED (marker file) guards every new branch and worktree; AUTO (default) always guards named worktree
   creation and guards branch-only or auto-named creation only when another lane exists; OFF
   (`git config --local magos.guard off`) silences the host hooks of that repository. `MAGOS_GUARD=off` is read from the
   host process environment only.
7. Tamper protection: a command that edits the guard's state (`core.hooksPath`, `GIT_CONFIG_*`, `git config magos.*`,
   `.git/hooks`, `.git/refs`, `<common>/magos`, `~/.magos`, or runs `override`, `arm`, `disarm`, `install`) is denied by
   the host hook.
8. Failure handling: any internal error denies only a call that was already recognised as lane creation; otherwise the
   hook prints `{}` and a warning on stderr. The launcher turns a missing script, missing Python or a non-zero guard exit
   into exit 2 for the strict group (EnterWorktree) and a warning with exit 0 for all other tools.

## Change Notes

`scripts/magos_guard.py` is a new file; it replaces the former behaviour in which lane conflicts were only advised after
diffs existed. Compatibility: no existing command, adapter, manifest key or test row changes. `references/lane-split.md`
is a new flat reference (shipped to Codex and Hermes by the existing `references/*.md` glob), `SKILL.md` gains one
invariant, one preflight bullet, one create-the-lane step and two hard stops, and `references/commands.md` gains the
open-claim active-owner rule, a release step in `/GitIntegrate` and a `list` step in `/GitRecon`. The root `description`
is unchanged (1017 characters). `hooks/hooks.json` and `hooks/run-guard.cmd` sit at the repository root, outside
`.claude-plugin/`. The git layer is opt-in per repository (`arm`) and the Codex and Hermes entries are generated, never
merged automatically. Known limits are stated in `references/lane-split.md` section 12: hooks read command text, the git
layer cannot see `-c core.hooksPath`, direct `.git/refs` writes, libgit2 or clones, harness-created worktrees are covered
only by the git layer, claims are per clone, and overrides are not access control.
