## Inline help

Usage: `/GitSweep <branch> [--apply] [--discard-ignored] [--push] [--remote <name>] [--lang <language>] [--help]`

- `<branch>`: Required local branch that receives everything. Matched exactly (case-sensitive); it must not be `main`.
- `--apply`: Run `/GitConverge <branch> --apply` first (merge every local branch's unique commits into `<branch>`, delete the merged local branches and their clean worktrees), then delete the remote branches that are already merged into a branch the remote keeps. A conflict or failed check stops the command before any deletion. It never moves or deletes `main`, and it pushes commits only with `--push`. Each remote deletion closes the open pull requests that use the branch as their head, and on some hosts closes or retargets those that use it as their base; the preview cannot see them.
- `--discard-ignored`: Passed through to the converge phase: also allow removing worktrees that hold ignored files (for example `.env`). Without it those worktrees and their branches are kept.
- `--push`: With `--apply`, after the converge phase and before the remote deletions, publish `<branch>` with one fast-forward push, exactly `git push --recurse-submodules=no --no-follow-tags <remote> refs/heads/<branch>:refs/heads/<branch>` (never forced, never `--no-verify`), so remote branches merged only into the local `<branch>` are deleted in the same run instead of needing a manual push and a second run. The push is refused when the remote's `<branch>` is not an ancestor of the local one, when `<branch>` is `main` or the remote default, when the converge phase stopped or its validation failed, or when the remote sweep is `UNKNOWN`. When the remote's `<branch>` already equals the local one nothing is pushed (`PUBLISH_NOT_NEEDED`); otherwise the push runs even when no remote branch depends on it. The preview counts the existing commits it would publish; the apply adds at most one merge commit per branch it merges, and its report gives the exact range and count. Without `--apply` the preview only predicts the push, and it gives that prediction whether or not `--push` was typed. A published branch cannot be undone by this command.
- `--remote <name>`: The remote whose merged branches are swept (`origin` when absent). It must be listed by `git remote`; otherwise the command stops before anything is changed and names the remedy.
- `--lang <language>`: Language of the reply, as a name or code (for example `English`, `ja`); Chinese when absent. Command names, options, branch names, paths, SHAs, and status codes stay untranslated.
- `--help`: Show this help and stop without inspecting or changing the repository.
- Default: Preview the converge plan and the remote branches that would be deleted, then a readiness verdict (`ONE_SHOT`, `PARTIAL` or `BLOCKED`) with the recommended command and the remedy for everything that remains; nothing is changed and the network is not contacted.

A remote branch is deleted only when its tip is already contained in the remote's own copy of `<branch>` or its default branch. A branch merged only into the local `<branch>` is `PUSH_THEN_DELETE` while the push is predicted to run, in the preview with or without `--push`: with `--push` the run publishes `<branch>` first and then deletes it, and without `--push` the run leaves it on the remote and reports "kept: `--push` not typed" (rerun with `--push`, or, once local `<branch>` holds its tip, push `<branch>` yourself and run `/GitSweep` again). It is `PENDING_PUSH` when the push is not predicted to run (for example `<branch>` is the remote default, or the remote's `<branch>` is not an ancestor of the local one) or when the run skipped the push, or the push failed or was not confirmed: clear the condition the report names, then rerun (with `--push`, except when `<branch>` is the remote default, which the command never pushes). To rerun after a remedy is to run the preview again and then the apply, because a remedy changes the repository and an apply whose plan is older than the repository stops with a new preview. A source branch, or a remote branch that is not `NOT_TOUCHED`, whose name holds a character outside ASCII letters, ASCII digits and `.` `_` `/` `+` `-`, or starts with `-` or `+`, is never passed to a command: such a source is `UNKNOWN` (rename it) and such a remote branch is `BLOCKED_BAD_NAME` (delete or rename it on the host). A remote with several URLs, or a push URL that differs from the fetch URL, makes the remote sweep `UNKNOWN`, because a push goes to every URL. A preview that is not `BLOCKED` ends with the recommended command, which carries exactly the flags that lift something (`--discard-ignored` when ignored files are the only blocker of a worktree, with the files it deletes listed, and `--push` when a branch is `PUSH_THEN_DELETE`, whether or not you typed it, or when you typed `--push` and the publish prediction says the push will run, with the commit count printed next to the line) and carries `--remote` and `--lang` as you gave them; a typed `--push` that cannot run is dropped from the line and the report says why. The verdict judges that command, not the one you typed: a preview shows the state that command reaches, and an apply uses the flags it was given. The end state is only `main` and `<branch>` as local branches, the worktrees of the deleted branches removed, and every remote branch deleted or `NOT_TOUCHED`; a worktree the command never touches (a detached one, or one that holds `main` or another kept branch) is listed in the report. An apply report ends with the run state `COMPLETE` or `PARTIAL`. A `PARTIAL` report ends with two lines, in this order: `Next preview:`, the same line without `--apply`, to run once the remedies are done so that the preview becomes the earlier plan, and `Next command:`, the line to run after that preview (when that preview recommends another line, run the recommended one). Both are built the same way, with the flags in the order `--apply`, `--discard-ignored`, `--push`, `--remote`, `--lang` (`--remote` and `--lang` as you gave them), and both are left out when no rerun would change anything. The `Next command:` line carries `--push` when some remote branch ended `PUSH_THEN_DELETE` or `PENDING_PUSH` for a reason that a rerun with `--push` can clear, or when `--push` was typed and the publish prediction says the push would still run; it never carries `--push` when the only reason is that `<branch>` is the remote default; with phase 2 `UNKNOWN` it carries `--push` only when it was typed.

Examples: `/GitSweep agent/release`, `/GitSweep agent/release --apply`, `/GitSweep agent/release --apply --push`, `/GitSweep agent/release --apply --remote upstream`, `/GitSweep --help`.
