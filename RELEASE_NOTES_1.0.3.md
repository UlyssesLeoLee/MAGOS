# MAGOS 1.0.3 — 加固与 GitSweep 改进版 / Hardening and GitSweep release

A hardening release of the lane guard (`scripts/magos_guard.py`, `hooks/run-guard.cmd`) and an improvement of `/GitSweep`: `--push`, a readiness verdict with a recommended command, a remedy for every failed gate, and a run state whose `PARTIAL` form ends with a `Next preview:` line and a `Next command:` line. **Every install of an earlier version should upgrade**, including the guard copies under `~/.magos/guard` that the Codex and Hermes hooks run. Full detail and upgrade steps: [CHANGELOG.md, section 1.0.3](https://github.com/UlyssesLeoLee/MAGOS/blob/v1.0.3/CHANGELOG.md).

## 版本概述

1.0.3 继续加固 lane guard（分支/工作树“车道”守卫），并让 `/GitSweep` 能一次做完。守卫读取以下各类写法：`git update-ref --stdin` 的指令（只读取 here-string、here-document 和直接管道送入的 `echo`/`printf`；带引号、转义、格式化或来源不可读的指令按动态创建拒绝）、被反斜杠/反引号/脱字符转义的程序名、`git rebase --ex`/`--exe`、`git --shallow-file`、`refs` 与 `heads` 任意大小写的 ref（`refs/HEADS`、`REFS/heads`；宿主 hook 与 git 层共用同一个模式）、`git update-ref` 与 `git symbolic-ref -m` 的选项以及动态的 ref 词、refspec 目标 `refs/heads/refs/<name>` 与空源的推送、git 接受的分支名（`update-ref`、`symbolic-ref`、`fetch`、`pull`、`push` 里以 `-` 开头的名字，非 ASCII 空白）、出现在程序词之前或 `git` 与子命令之间的重定向（`>/dev/null git switch -c x`）、`git branch` 的合并短选项（`-df` 是删除，`-m -r a b` 是重命名）、`Start-Process -WorkingDirectory`、`powershell`/`pwsh` 的各种选项拼写与 PowerShell 的反引号、不存在目录之后的创建、以及启动器在 `py` 退出 103/112 时改用下一个解释器。两处行为变化：输入来自文件或另一条命令的 `update-ref --stdin`，即使只是删除也按动态创建拒绝；长度超过 4096 个字符的目录写法按未知目录处理，一长串 `-C` 选项和很深的括号嵌套则在与命令长度成线性的时间内读完。`/GitSweep` 新增 `--push`：收敛之后把 `<branch>` 以一次快进推送发布到远端，只合并进本地 `<branch>` 的远端分支就能在同一次运行里清除；远端已经停在本地位置时不推送（`PUBLISH_NOT_NEEDED`）。预览末尾给出“一次完成就绪度”（`ONE_SHOT` / `PARTIAL` / `BLOCKED`）、推荐命令（`--remote`、`--lang` 照抄，有 `PUSH_THEN_DELETE` 的分支时不管有没有写 `--push` 都带上它，写了 `--push` 且推送预计会执行时也带上它）和每个遗留项的处理办法；判定评判的是推荐命令，而不是你敲的命令；目标状态里不含命令从不去碰的工作区，报告会把它们列出来。执行报告以 `COMPLETE` 或 `PARTIAL` 收尾，`PARTIAL` 时以 `Next preview:` 与 `Next command:` 两行收尾：先运行预览，再运行命令。

## Highlights

- **`update-ref --stdin` read from what the hook can see.** The instructions come from a here-string, the here-documents of the line and a directly piped `echo`, `printf`, `Write-Output`, `Write-Host` or `cat`; a record is denied as unparseable unless every `create` and `update` is a plainly read name, so a quote, an escape other than `\0`, `\n`, `\t` and `\r`, an expansion, an empty name, a name git refuses and an unreadable source (a file, another command) make it dynamic.
- **Escaped program words read.** `g\it`, ``g`it`` and `g^it` in a shell the hook cannot name are read as `git`; PowerShell's backtick is its escape character with its special sequences, and the gate that decides whether a line is read sees words without escapes and quotes and words that run a script or a shell.
- **More git spellings read.** `git rebase --ex` and `--exe`, `git --shallow-file <value>`, the options of `git update-ref`, `git symbolic-ref -m`, and `refs/HEADS/x` and `REFS/heads/x` in any letter case of `refs` and `heads` (host hook and the `reference-transaction` backstop, one shared pattern) are judged like their plain forms; the alias check reads the subcommand after the values of every global option in one pass.
- **Redirections and `git branch` options.** A redirection before the program word, between `git` and its subcommand or among its words is skipped with its target (`>/dev/null git switch -c x`, `git branch -m old new >/dev/null`), and the short options of `git branch` are read as git reads them (`-df` deletes, `-m -r a b` creates `b`).
- **Refs and names.** A refspec destination `refs/heads/refs/x` creates the branch `refs/x`, a push refspec with an empty source deletes, a dynamic ref word of `git update-ref` or `git symbolic-ref` is a dynamic creation, and the names git accepts (a leading dash for `update-ref`, `symbolic-ref`, `fetch`, `pull` and `push`, whitespace outside ASCII) are creations.
- **Time bounds.** A directory spelling longer than 4,096 characters is an unknown directory; a chain of `-C` options and deeply nested groups are read in time linear in the length of the command.
- **PowerShell read more completely.** `Start-Process git` runs in its `-WorkingDirectory`; every spelling of `-Command`, `-CommandWithArgs` and `-EncodedCommand` of `powershell` and `pwsh` is read in the walk, the tamper filter and a Codex argv.
- **Directories and claims.** A creation after a `cd` to a missing directory is judged in the directory the shell is in at that point; a claim stored under a name the Windows alias rule refuses allows the creation of its branch, and `list` and `doctor` name it.
- **Launcher.** Both halves pass on to the next interpreter when `py` exits 103 or 112.
- **`/GitSweep --push`.** With `--apply`, one fast-forward push of `<branch>` (`git push --recurse-submodules=no --no-follow-tags <remote> refs/heads/<branch>:refs/heads/<branch>`, never forced, never `--no-verify`) runs after the converge phase and before the remote deletions, so remote branches merged only into the local `<branch>` are deleted in the same run. When the remote's `<branch>` already equals the local tip nothing is pushed (`PUBLISH_NOT_NEEDED`); otherwise the push runs even when no remote branch depends on it.
- **One-shot readiness.** The `/GitSweep` preview ends with `ONE_SHOT`, `PARTIAL` or `BLOCKED`, a recommended command (with `--remote` and `--lang` as given) that carries exactly the flags that lift something, `--push` included whether or not it was typed when a remote branch is `PUSH_THEN_DELETE`, and when it was typed and the push is predicted to run, and the remaining items with their remedies; the verdict judges the recommended command, not the command as typed. Every failed gate is reported at once with its remedy, in `/GitConverge` too, and a `--remote` that `git remote` does not list is a gate of `/GitSweep`.

## New

- `/GitSweep <branch> --apply --push`, with `PUBLISH_NOT_NEEDED` when the remote branch already sits at the local tip, and `PUSH_SKIPPED`, `PUSH_FAILED` and `PUSH_UNCONFIRMED` for a push that does not run, fails, or does not move the remote branch to the local tip; the preview predicts the push from local refs, with or without `--push`, without the network.
- The readiness block of the `/GitSweep` preview: verdict, recommended command (`--discard-ignored` with the ignored files it deletes listed, `--push` with the commits it publishes), remaining items.
- The **Remedies** table of `references/commands.md` section 6, used by `/GitConverge` and `/GitSweep`, and the remedies for remote findings in section 7.
- The run state `COMPLETE` or `PARTIAL` at the end of the `/GitSweep` apply report, with two lines for `PARTIAL`, `Next preview:` (the same line without `--apply`, to run first so that the preview becomes the earlier plan) and `Next command:` (the line to run after that preview), whose flags come in the order `--apply`, `--discard-ignored`, `--push`, `--remote`, `--lang` with `--remote` and `--lang` as given. The `Next command:` line carries `--push` when some remote branch ended `PUSH_THEN_DELETE` or `PENDING_PUSH` for a reason that a rerun with `--push` can clear, or when `--push` was typed and the publish prediction says the push would still run; it never carries `--push` when the only reason is that `<branch>` is the remote default; with phase 2 `UNKNOWN` it carries `--push` only when it was typed. The end state leaves out a worktree the command never touches (a detached one, or one that holds `main` or another kept branch); the report lists it.
- Remote sweep safety: every git command runs as an argument list, never as a shell string; the name of a source branch, or of a remote branch that is not `NOT_TOUCHED`, outside ASCII letters, ASCII digits and `.` `_` `/` `+` `-` (or starting with `-` or `+`) is never passed to a command (`UNKNOWN` for a local source, `BLOCKED_BAD_NAME` for a remote branch); a remote with several URLs, or a push URL that differs from the fetch URL, and a live remote `HEAD` that names no branch make the sweep `UNKNOWN`; both push commands carry `--recurse-submodules=no`.
- `BLOCKED_SUBMODULE` follows git's own test (a `modules` directory in the worktree's git directory, or a populated submodule path), deinitializing does not lift it, and its remedy is to remove the worktree yourself or keep it; `PREDICTED_IGNORED_OVERLAP` marks in the preview the ignored-file overlap that stops an apply.
- Documentation: `README.ja.md`, a Japanese edition that follows the Chinese README section for section; all three READMEs share one language switcher and describe the 1.0.3 commands, the command names per host and the install steps.

## Changed

- A remote branch is classified against the converged target, so a preview and the apply after it agree: `PUSH_THEN_DELETE` when the publish step is predicted to run, in a preview with or without `--push` (an apply without `--push` leaves it and reports "kept: `--push` not typed"), and `PENDING_PUSH` when no push of the run clears it (the publish is not predicted to run, or the push was skipped, failed or unconfirmed). The remedies differ: rerun with `--push` or, once local `<branch>` holds its tip, push `<branch>` by hand for the first, clear the condition the report names for the second.
- The gates of `/GitConverge` and `/GitSweep` are evaluated all at once, each failed gate with its remedy; `/GitSweep` adds the gate `--remote <name>` not listed by `git remote`, and a failed gate makes its verdict `BLOCKED`.
- The `/GitSweep` hard stop on pushing reads: no commits or tags except the one fast-forward push of `<branch>` that `--push` makes; the other push is the lease-guarded deletion of one named remote branch at a time, and `/GitConverge` pushes nothing.
- The `Default` line of the `/GitConverge` help says that every failed gate and blocker is followed by the action that lifts it.
- The one-line hints of `git-sweep` list `[--apply] [--push] [--help]`; the full usage lists every option.
- An `update-ref --stdin` whose input is a file, another command or text with an expansion is denied as a dynamic creation even when it only deletes; the hook reads the instructions only from a here-document, a here-string or a piped `echo`, `printf`, `Write-Output` or `Write-Host`.
- A directory spelling longer than 4,096 characters is an unknown directory: a creation in the same invocation as a chain of `-C` values or `cd` targets that long is denied as unparseable where creations are guarded.

## 升级 / Upgrade

1. Upgrade the plugin on each host (`references/installation.md`) and **restart every running Claude Code session**. A Hermes install pinned with `--ref` must move its pin: `hermes plugins install UlyssesLeoLee/MAGOS --ref <40-char SHA of v1.0.3> --force --enable`.
2. Run `doctor` from the new version, then the `install --host <host>` commands it prints in your own terminal; compare each printed snippet with your host config and replace the entry if it differs.
3. In armed repositories, run `doctor` and re-run `arm`: the git-layer hook reads `refs` and `heads` in any case, so `doctor` reports the installed hook as different until `arm` runs again.
4. Nothing else changes for scripts.

Claim files of 1.0.0 to 1.0.2 are read unchanged.

## Known issues

- Every host receives the whole repository (including `tests/`, `.quality/`, `.github/`) because the marketplace source is the repo root; a slim runtime payload is not part of 1.0.3.
- The lane guard's own limits are listed in `references/lane-split.md`, section 12.
- `/GitSweep --push` publishes with a plain fast-forward push and cannot undo it; undoing a publish takes a force push, which the command never makes.
- **Lane guard limits.** The lane guard is a best-effort detector of the text of one command line, not a parser of every shell. The git-layer backstop (`arm`) is the enforcement that does not depend on parsing: in an armed repository it vetoes a branch created without a claim whatever tool ran the git binary, within the backstop limits listed in `references/lane-split.md` section 12. Keep the repositories where lanes live armed, run the commands that matter through a script you have reviewed, and stay on the lane discipline of the skill. The hooks do not read these classes:
  - Aliases from places the hook does not read: `--config-env`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_GLOBAL`, `-c include.path`, an alias defined on the same line, the aliases of another repository or of a session outside any repository, `-c alias.*` in another case or shadowing a built-in, chains over three aliases and git spelled `git.exe`, `Git` or as a variable are not read; keep the repository the line reaches armed.
  - Command text from configuration or environment: `core.fsmonitor`, `core.editor`, `sequence.editor`, `diff.external`, `GIT_EDITOR`, `GIT_SEQUENCE_EDITOR`, `GIT_EXTERNAL_DIFF` and a `rebase --exec` or `bisect run` text with a dynamic program are not inspected; keep the repository armed.
  - Wrappers and program spellings outside the walker's lists: `ionice`, `flock`, `taskset`, `coproc` and similar wrappers, a path-qualified `env`, `nohup`, `xargs` or `sudo`, ANSI-C quoting (`$'g\x69t'`), a backslash-newline inside the program word, an empty expansion or a substitution as the program, a program held in a variable or computed, and shells such as `fish` and `tcsh` hide the program; run what matters through a reviewed script and keep the repository armed.
  - Escapes in git words in a tool whose shell is not known: In a tool whose shell is unknown, a backslash inside a git option word (`-\C`, `--git\-dir=`), a sub-subcommand (`worktree a\dd`) or the ref of `update-ref` is compared as written; keep the repository armed.
  - Text fed to a shell, and scripts: A creation inside a process substitution, quoted text that names no git fed to a shell (`printf '. ../mk\n' | sh`), a script run directly without a `.sh`, `.bash` or `.ps1` name (`./mk`) and a script another command feeds (`cat ../mk | bash`) are not read; read the script first and keep the repository armed.
  - A directory an earlier command of the line creates: A `cd` into a directory that `mkdir` creates earlier on the line is followed only in a `&&` chain (`mkdir L/nd; cd L/nd; git switch -c x`); create the directory in a call of its own or chain with `&&`, and keep the repository armed.
  - Pushes and fetches without a readable destination: `fetch --refmap` and `-c remote.<name>.fetch`, a push into another local repository without a colon refspec (`git push ../R newb`, `--all`, `--mirror`, `HEAD`) and a push whose repository a bundled option value displaces (`-fo x`) are not read; arm the receiving repository too.
  - The symbolic-ref alias two-step: A symbolic ref outside `refs/heads/` that points into it, then written through `git update-ref`, creates the branch unseen; keep the repository armed.
  - Nested substitution: A substituted text with another group inside it (`$(git switch -c x $(git rev-parse HEAD))`, `(git switch -c x (git rev-parse HEAD))`) is not read; keep the repository armed.
  - PowerShell tokenising: A `\"` or doubled backtick before a quote in a double-quoted string, a trailing backslash that joins the next line, a here-string with an apostrophe and a block comment `<# .. #>` are tokenised approximately, so the creation after them can go unjudged and a command-shaped line inside them is denied; keep the repository armed.
  - PowerShell code from strings: PowerShell code built from a string and run through a script block (`[scriptblock]::Create`) and a program called by a dot (`. git switch -c x`) are not read; keep the repository armed.
  - The switches of `cmd` and its `start`: `cmd` switches other than a lone `/c` or `/k` (`/r`, `/d/c`, `/cgit`) and `cmd /c start` are not read; keep the repository armed.
  - `Start-Process` of shells and splatting: A shell that `Start-Process` starts, a call through splatting and an `-ArgumentList` cut at commas and read with shell quoting are not read as written; keep the repository armed.
  - Options of child shells: `pwsh -WorkingDirectory`, a `powershell -File` script behind four option values and `env -S` with bundled options (`-vS`) or the `\_` separator are not read; keep the repository armed.
  - The tamper filter: The tamper filter does not follow `Start-Process` lists, `cmd /r`, `env -S`, `iex` and `ScriptBlock::Create`, so the git layer itself can be removed; run `doctor` to see that it is still installed and re-run `arm` when it is not.
  - MCP tools without a string `command`: MCP command tools whose command is a list or sits under another key (`cmd`, `script`, `argv`, `commandLine`, `input`) are allowed without parsing; keep the repository armed.
  - Over-denials by text or name: A prompt that mentions `isolation: worktree`, quoted git text beside a here-string, an MCP tool named `get_branch`, the help forms of `gh pr checkout`, `git config magos.<key>` as a read and git options that print and exit are denied although they create nothing; run them in your own terminal.
  - Unreadable `update-ref --stdin`: An `update-ref --stdin` fed from a file, another command or text with an expansion is denied as dynamic even when it only deletes; the hook reads it only when a here-document, a here-string or a piped `echo` or `printf` feeds it.
  - Launcher input cost: The sh half of the launcher costs quadratic time for a payload of tens of thousands of raw lines; no agent can cause it, and a host that pretty-prints its payload should send one line.
- **车道守卫的已知限制（中文）。** lane guard 是对单条命令行文本的尽力检测（best-effort），不是对每一种 shell 的完整解析；不依赖解析的强制执行是 git 层后盾（`arm`）：在已 arm 的仓库里，无论由哪个工具运行 git 二进制，没有 claim 的分支创建都会被否决，但仍受 `references/lane-split.md` 第 12 节所列后盾自身限制的约束。请让承载车道的仓库保持 arm 状态，把重要命令放进你审阅过的脚本里运行，并遵守技能的车道纪律。hook 不读取以下几类写法：
  - `--config-env`、`GIT_CONFIG_COUNT`、`GIT_CONFIG_PARAMETERS`、`GIT_CONFIG_GLOBAL`、`-c include.path`、同一行里定义的别名、其他仓库或无仓库会话的别名、大小写不同或与内置命令同名的 `-c alias.*`、超过三层的别名链，以及写成 `git.exe`、`Git` 或变量的 git，hook 都不读取；请让命令实际到达的仓库保持 arm。
  - git 从配置或环境变量里运行的命令文本（`core.fsmonitor`、`core.editor`、`sequence.editor`、`diff.external`、`GIT_EDITOR`、`GIT_SEQUENCE_EDITOR`、`GIT_EXTERNAL_DIFF`）以及程序名动态的 `rebase --exec` / `bisect run` 文本不被检查；请保持仓库 arm。
  - walker 列表之外的包装器与程序写法会藏住程序：`ionice`、`flock`、`taskset`、`coproc` 等，带路径的 `env`、`nohup`、`xargs`、`sudo`，ANSI-C 引号（`$'g\x69t'`），程序名中间的反斜杠加换行，空展开或命令替换拼出的程序名，放在变量里或算出来的程序，以及 `fish`、`tcsh` 等 shell；重要命令请放进审阅过的脚本里运行，并保持仓库 arm。
  - 在 shell 未知的工具里，git 选项词（`-\C`、`--git\-dir=`）、子子命令（`worktree a\dd`）或 `update-ref` 的 ref 中的反斜杠按原样比较；请保持仓库 arm。
  - 进程替换里的创建、不含 git 字样而被送进 shell 的带引号文本（`printf '. ../mk\n' | sh`）、没有 `.sh`/`.bash`/`.ps1` 扩展名而直接运行的脚本（`./mk`），以及由另一条命令喂给 shell 的脚本（`cat ../mk | bash`）不被读取；请先审阅脚本，并保持仓库 arm。
  - 只有 `&&` 链才会跟随同一行里先由 `mkdir` 创建、再 `cd` 进去的目录（`mkdir L/nd; cd L/nd; git switch -c x` 不会）；请把创建目录单独成一次调用或改用 `&&`，并保持仓库 arm。
  - `fetch --refmap` 与 `-c remote.<name>.fetch`、推送到另一个本地仓库而不带冒号的 refspec（`git push ../R newb`、`--all`、`--mirror`、`HEAD`），以及仓库参数被带值的合并短选项顶替的推送（`-fo x`）不被读取；接收方仓库也要保持 arm。
  - 建在 `refs/heads/` 之外、指向其中分支的符号引用，随后用 `git update-ref` 经它写入，会在 hook 看不见的情况下创建分支；请保持仓库 arm。
  - 内部还含有括号组的替换文本（`$(git switch -c x $(git rev-parse HEAD))`、`(git switch -c x (git rev-parse HEAD))`）不被读取；请保持仓库 arm。
  - PowerShell 的近似词法（双引号字符串里的 `\"` 与成对反引号加引号、行尾反斜杠接下一行、含撇号的 here-string、块注释 `<# .. #>`）会让其后的创建未被判定，其中形如命令的行还会被误拒；请保持仓库 arm。
  - 经 ScriptBlock 运行、由字符串构造的 PowerShell 代码（`[scriptblock]::Create`）以及用点调用的程序（`. git switch -c x`）不被读取；请保持仓库 arm。
  - `cmd` 除单独的 `/c`、`/k` 之外的开关写法（`/r`、`/d/c`、`/cgit`）与 `cmd /c start` 不被读取；请保持仓库 arm。
  - `Start-Process` 启动的 shell、经 splatting 的调用，以及被逗号切开并按 shell 引号规则读取的 `-ArgumentList`，都不按其真实含义读取；请保持仓库 arm。
  - `pwsh -WorkingDirectory`、排在四个选项值之后的 `powershell -File` 脚本，以及带合并选项（`-vS`）或 `\_` 分隔符的 `env -S` 不被读取；请保持仓库 arm。
  - 防篡改过滤器不跟随 `Start-Process` 参数列表、`cmd /r`、`env -S`、`iex`、`ScriptBlock::Create`，因此 git 层本身可能被移除；请运行 `doctor` 确认它仍已安装，否则重新 `arm`。
  - 命令不是字符串 `command` 的 MCP 命令工具（列表，或放在 `cmd`、`script`、`argv`、`commandLine`、`input` 下）不经解析直接放行；请保持仓库 arm。
  - 提到 `isolation: worktree` 的提示词、here-string 旁带引号的 git 文本、名为 `get_branch` 的 MCP 工具、`gh pr checkout` 的帮助写法、被当作读取的 `git config magos.<key>`，以及只打印就退出的 git 选项，虽然不创建任何东西也会被拒；请在自己的终端里运行。
  - 输入来自文件、另一条命令或带展开文本的 `update-ref --stdin`，即使只是删除也按动态创建拒绝；只有 here-document、here-string 或管道送入的 `echo`/`printf` 提供的输入才会被读取。
